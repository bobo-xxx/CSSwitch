# Codex Responses Lite compatibility contract

Research date: 2026-07-29

Scope: request capabilities, status/retry semantics, subscription authentication, and diagnostics for CSSwitch's Codex Provider Route. No credentials, authentication stores, prompts, user data, or live subscription requests were inspected.

## Evidence boundary

- **Official fact** means a current OpenAI-owned public document or official SDK source.
- **Local observation** means behavior visible verbatim in this CSSwitch checkout and its tests.
- **Inference** means the compatibility rule proposed from those facts and observations; it is not a published promise from the private upstream.

The central limitation is important: OpenAI publicly documents the standard Responses API, but does not document a product or API named **Responses Lite**, the `https://chatgpt.com/backend-api/codex/responses` endpoint, the `x-openai-internal-codex-responses-lite` header, the `ChatGPT-Account-ID` header, or the `additional_tools` input item. Those are therefore private/undocumented behaviors in this report, even where CSSwitch has fixtures for them.

## Compact compatibility matrix

| Area | Official OpenAI fact | CSSwitch local observation | Contract CSSwitch should honor |
|---|---|---|---|
| Responses Lite surface | The public Responses API is the documented surface for model requests and tool use. No public OpenAI reference found in scope defines Responses Lite. [Responses create reference](https://developers.openai.com/api/reference/resources/responses/methods/create) | The Codex endpoint is the private ChatGPT backend; model metadata selects `use_responses_lite`, CSSwitch reshapes tools into `additional_tools`, sets `reasoning.context=all_turns`, disables parallel tools, and sends an internal Lite header. [`config.rs:67-71`](../../desktop/gateway/src/config.rs#L67-L71), [`codex_protocol.rs:321-478`](../../desktop/gateway/src/codex_protocol.rs#L321-L478), [`codex_transport.rs:269-307`](../../desktop/gateway/src/codex_transport.rs#L269-L307) | **Inference:** Treat Lite as a versioned provider capability learned from the account's model catalog, not as standard Responses. Fail closed when the capability/shape is unknown; do not claim public API compatibility for private fields. |
| `tool_choice` | Standard Responses documents `none`, `auto`, `required`, and forced tool choices. [Responses create reference](https://developers.openai.com/api/reference/resources/responses/methods/create) | Lite accepts only an absent or `auto` incoming choice; CSSwitch rejects `none`, `any`/`required`, and named tools *before transport* with its own 400 `invalid_request_error`. It then emits `"tool_choice":"auto"`. [`codex_protocol.rs:352-419`](../../desktop/gateway/src/codex_protocol.rs#L352-L419), [`codex_protocol.rs:2493-2564`](../../desktop/gateway/src/codex_protocol.rs#L2493-L2564), [`server.rs:1110-1118`](../../desktop/gateway/src/server.rs#L1110-L1118) | **Inference:** The exact message `tool choice is unsupported for Responses Lite` is a CSSwitch capability error, not evidence of an OpenAI outage. Omission/normalization is safe only when semantically equivalent to `auto`; silently changing `none`, `required`, or a forced tool to `auto` is not equivalent. Return a typed, non-retryable capability error for non-equivalent choices. |
| 401 authentication | OpenAI classifies 401 as invalid authentication and documents revoked/wrong credentials, wrong organization/project, missing permissions, and IP authorization among possible causes. [Error codes](https://developers.openai.com/api/docs/guides/error-codes) | CSSwitch preserves 401, invalidates the model catalog, and may refresh OAuth for the *next* request; it never replays the rejected inference POST. [`codex_transport.rs:342-353`](../../desktop/gateway/src/codex_transport.rs#L342-L353), [`server.rs:1194-1233`](../../desktop/gateway/src/server.rs#L1194-L1233), [`server.rs:3014-3087`](../../desktop/gateway/src/server.rs#L3014-L3087) | **Inference:** Classify as `authentication`, non-retryable for the current POST. Preserve status 401, invalidate dependent catalog state, refresh/re-authenticate out of band, and tell the caller to retry a new request. Never label it Claude/OpenAI temporary unavailability. |
| 403 authorization | Public API docs identify 403 for unsupported geography. Codex subscription use is additionally governed by ChatGPT workspace permissions and RBAC. [Error codes](https://developers.openai.com/api/docs/guides/error-codes), [Codex authentication](https://learn.chatgpt.com/docs/auth) | CSSwitch preserves 403 and invalidates model state, but does not refresh or replay. [`codex_transport.rs:342-353`](../../desktop/gateway/src/codex_transport.rs#L342-L353), [`server.rs:3014-3060`](../../desktop/gateway/src/server.rs#L3014-L3060) | **Inference:** Classify as `authorization`/`entitlement`, non-retryable without an account, workspace, policy, or route change. Preserve 403 and provide a sanitized permission/workspace recovery hint. |
| 429 rate/quota | OpenAI documents both request-rate exhaustion and quota/spend exhaustion as 429. It recommends capped exponential backoff for rate errors and warns failed attempts also consume the limit. [Error codes](https://developers.openai.com/api/docs/guides/error-codes), [Rate limits](https://developers.openai.com/api/docs/guides/rate-limits) | CSSwitch preserves 429 but performs exactly one POST; it does not parse a safe error category or expose rate-limit timing. [`codex_transport.rs:241-253`](../../desktop/gateway/src/codex_transport.rs#L241-L253), [`codex_transport.rs:342-353`](../../desktop/gateway/src/codex_transport.rs#L342-L353), [`server.rs:3089-3130`](../../desktop/gateway/src/server.rs#L3089-L3130) | **Inference:** Preserve 429. Distinguish a safely allowlisted `rate_limit` from `quota` when possible; only the former is retryable. If the private response cannot be safely classified, report 429 with bounded retry guidance rather than converting it to 502. |
| `Retry-After` and reset signals | OpenAI's public rate guide documents `x-ratelimit-reset-*` response headers. The official Python SDK honors reasonable `retry-after-ms`/`Retry-After` values (up to 60 seconds), otherwise using short exponential backoff. [Rate-limit headers](https://developers.openai.com/api/docs/guides/rate-limits), [official SDK retry source](https://github.com/openai/openai-python/blob/main/src/openai/_base_client.py) | The inference transport does not read or retain any retry/reset header. [`codex_transport.rs:318-353`](../../desktop/gateway/src/codex_transport.rs#L318-L353) | **Inference:** If the private endpoint supplies a valid `Retry-After`, `retry-after-ms`, or documented reset header, honor it within a configured cap and expose only a normalized delay/reset value. No public source found guarantees that Responses Lite emits any of these headers. |
| Other 4xx | The official Python SDK retries 408 and 409, but not other 4xx; the error guide treats ordinary client/auth/permission failures as actionable rather than transient. [Official SDK retries](https://github.com/openai/openai-python#retries), [Error codes](https://developers.openai.com/api/docs/guides/error-codes) | Apart from 401/403/429, every rejected upstream status—including 400, 404, 408, 409, and 422—is mapped to downstream 502 with the same generic message. The upstream numeric status remains only in the internal error value and is dropped from the Anthropic-compatible JSON. [`codex_transport.rs:342-353`](../../desktop/gateway/src/codex_transport.rs#L342-L353), [`server.rs:228-287`](../../desktop/gateway/src/server.rs#L228-L287), [`server.rs:1138-1149`](../../desktop/gateway/src/server.rs#L1138-L1149) | **Inference:** Preserve the sanitized upstream class/status. Treat 400/404/422 and other permanent 4xx as non-retryable; treat 408/409 as transient only under a bounded retry policy. Never disguise a permanent request/capability error as a gateway 502. |
| Network and 5xx | OpenAI's error guide recommends retrying 500/503 after a brief wait. The official Python SDK retries connection errors, 408, 409, 429, and 5xx twice by default with short exponential backoff. [Error codes](https://developers.openai.com/api/docs/guides/error-codes), [official SDK retries](https://github.com/openai/openai-python#retries) | CSSwitch disables reqwest retries and documents exactly one inference POST. Network errors become 502, response timeout becomes 504, and every upstream 5xx becomes generic 502. [`codex_transport.rs:241-270`](../../desktop/gateway/src/codex_transport.rs#L241-L270), [`codex_transport.rs:318-353`](../../desktop/gateway/src/codex_transport.rs#L318-L353) | **Inference:** Network/408/409/429-rate/5xx are the transient set for a bounded policy. However, the private Lite endpoint has no published idempotency contract, so automatic replay is not an official guarantee; any replay policy must be explicitly bounded, stop once SSE bytes arrive, and remain distinguishable from a caller-created new request. |
| Subscription authentication | Codex officially supports either ChatGPT sign-in for subscription access or API-key sign-in for usage-based access. ChatGPT sign-in follows workspace permissions/RBAC/retention; API-key use is separately billed and may lack ChatGPT workspace features. Browser sign-in returns credentials to the Codex client. [Codex authentication](https://learn.chatgpt.com/docs/auth) | CSSwitch uses a short-lived in-memory OAuth snapshot, sends bearer plus account ID headers, makes secret-bearing headers sensitive, prevents debug serialization, and zeroizes token/account material on drop. A 401 refresh is only for a subsequent request. [`codex_auth/storage.rs:351-385`](../../desktop/gateway/src/codex_auth/storage.rs#L351-L385), [`codex_auth/storage.rs:582-642`](../../desktop/gateway/src/codex_auth/storage.rs#L582-L642), [`codex_auth/storage.rs:871-905`](../../desktop/gateway/src/codex_auth/storage.rs#L871-L905), [`codex_transport.rs:278-304`](../../desktop/gateway/src/codex_transport.rs#L278-L304) | **Inference:** Keep ChatGPT subscription OAuth distinct from Platform API-key authentication. Do not fallback between them, share credentials, or infer entitlement from authentication alone. A valid login can still receive authorization, workspace, model, quota, or geography failures. |

## Diagnostic and redaction boundary

**Official facts.** OpenAI recommends logging the response `x-request-id`; documented Responses endpoints also accept a unique ASCII `X-Client-Request-Id` for tracing requests that time out before a response arrives. OpenAI explicitly treats API credentials as secrets. [API overview: authentication and request IDs](https://developers.openai.com/api/reference/overview)

**Local observations.** CSSwitch currently returns only the Anthropic-compatible `type`, `error.type`, and a static `error.message` for inference failures. It neither sends a client request ID nor retains `x-request-id`, retry headers, attempt count, or upstream status in the downstream error. It intentionally avoids copying upstream error bodies and tests that HTML/JSON challenge bodies do not appear in diagnostics. [`server.rs:228-287`](../../desktop/gateway/src/server.rs#L228-L287), [`codex_transport.rs:116-156`](../../desktop/gateway/src/codex_transport.rs#L116-L156), [`codex_transport.rs:638-665`](../../desktop/gateway/src/codex_transport.rs#L638-L665)

**Inferred safe diagnostic fields:** provider (`codex`), route mode (`responses_lite`), mapped status, upstream status, sanitized failure class, retryability, normalized retry delay/reset, local correlation ID, allowlisted `x-request-id`, attempt count, and stage timing. Optional structured metadata can extend the existing Anthropic-compatible envelope without changing its three existing fields.

**Redact completely:** `Authorization`, access/refresh/ID tokens, `ChatGPT-Account-ID`, OAuth records, account identifiers/hashes in caller-visible errors, request and response bodies, prompts/history/tool arguments, raw upstream error/challenge bodies, cookies, private URLs, and credential-store paths. `X-Client-Request-Id` is correlation, not authentication and not an idempotency guarantee.

## Bottom line

Responses Lite is an undocumented subscription route, so its current body shape cannot be elevated to an official OpenAI contract. The evidence does establish a robust CSSwitch boundary: capability errors and permanent 4xx must remain typed and non-retryable; 401 and 403 must remain authentication/authorization failures; 429 and transient failures must retain safe retry signals; and diagnostics should preserve allowlisted status/correlation data without ever forwarding credentials, user content, or raw upstream bodies.
